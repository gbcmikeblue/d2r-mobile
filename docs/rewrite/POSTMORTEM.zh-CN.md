# 安卓支线复盘：五个失败的决定（2026-10-17）

> **这份文档是干什么的**：把 `d2r-mobile` 安卓支线「M2 的验收「屏幕出（游戏自己的）画面」一直没过」

> 正确做法是什么、以及**现在仍在重复**的是哪几处。
>
> **口径来源**：仓库内文档（`ANDROID_REWRITE.zh-CN.md` / `ANDROID_PROGRESS.zh-CN.md` /
> `ANDROID_PLAN.zh-CN.md`）、`dm/android` 代码、`git log`（截至 `54f2c2d`）；对照对象是另一仓库
> `d:/project/d2r-android`（同源分支：同一套 `dm/host`，`dm/gfx/nvn` 只差 `nvn_dirty.c` 411 行与
> `hle_nvn.c` 56 行）。**本轮只做离线比对与文档阅读，没有新的真机读数。**
>
> **边界（先写在这里，避免误读）**：本文**不**否定「宿主可复用」（探路 A：87 个编译单元里 56 个零改动）、
> **不**否定着色器链产出 SPIR-V、**不**否定 N4-h 已证明的「通道 / 附件 / 布局 / 清 / 视口这一层是好的」。

## 0. 一句话

走错的不是「选了 Vulkan」，而是：**在「客体内存怎么变成 GPU 能读的字节」这个唯一前置问题上选了设备
不支持的那条（零拷贝别名），并在自己的文档已经写明此路不通之后又排查了 19 轮；接着把验收判据换成一个
会随装载路翻转的代理指标，用 17 个里程碑去收敛它。**

## 2. 五个失败的决定

### 2.1 决定一：客体内存用「零拷贝别名」（最贵的一条）

- **做法**：`dm/android/vk/vk_region.c:1-13` —— 分配可导出的 `VkDeviceMemory` → `vkGetMemoryFdKHR` 取 fd →
  `mmap(MAP_FIXED)` 把客体池**原地**铺成 GPU 内存；甲案不可用时退 `AHardwareBuffer` 同形支路。
- **四条真机证伪**（全部记在 `ANDROID_REWRITE.zh-CN.md:60-67`）：Mali-G610 上甲案不存在；AHB 支路把内核
  打崩重启三次（`LDADDAL` → `SIGBUS`）；4 GB 池撞 `maxStorageBufferRange`；池子不在换轨段就 `g_pool_no_region` 报红。
- **更硬的证据**：`ANDROID_PLAN.zh-CN.md:393` 原文就写着「**所以「把池子指针直接包成缓冲」这条路在
  Vulkan 上不通，设计必须改。**」——「改」被推迟，接下来的 19 轮（M3-2k → M3-3e）仍在这个前提上排查。
- **代价**：19 轮真机 + 三条「假 bug 状」的排除结论；期间第二台设备累计重启 5 次。
- **正确做法**（对照方实际采用的）：**放弃别名，改为「只读快照 + 脏页增量 + 显式回读」**——
  `nvn_dirty.c`（411 行）、`pending_ranges.c`、`nvn_vulkan_delta.inc`、`nvn_vulkan_guest_publish.inc`、
  `nvn_vulkan_batch_resources.inc`；文档 `ANDROID_GPU_SNAPSHOT_DELTA_PLAN.zh-CN.md:48` 明确写「LAS 的标准匿名 heap
  导入在系统和 T30 上实际都缺 `VK_EXT_external_memory_host`，不继续直接移植」。
- **为什么这是分水岭**：这条路决定 GPU 读到的池字节**来自哪里**。前者要求「客体地址就是 GPU 内存」
  （设备不给），后者每帧把脏页搬进后备资源（任何设备都能跑）。**不是性能差别，是有没有画面。**

### 2.2 决定二：文档判了死刑之后，又排查了 19 轮

- 这不是「判断失误」，是**执行纪律**问题：写下了「设计必须改」，动作却是「继续排查」。
- **同一形态在后面还出现过一次**：N4 系列已经量到「两臂共有 15 种 VUID、只 A 0 种」（N4-g）⇒ 说明成因在两臂
  共用的代码里，而不是新地基；但后续仍以「在整局游戏上叠一个开关」的方式逐项试。
- **正确做法**：凡「文档已写好结论、代码还没改」的条目，进一个**待改清单**，改完才允许开下一轮实验；
  不允许把「已知不通的前提」当实验底座。

### 2.3 决定三：地基没走完就抓像素（顺序错）

- N0 / N1 / N2 / N3 完成的是**池 / 上传窗口 / 提交侧**；而「资源身份 → 绑定 → 描述符 → 管线状态全字段」
  这条数据通路没走完，就先去追「为什么这一次 draw 不落屏」。
- 结果 17 个 N4 里程碑抓到的是三条**语义平移**级 bug：
  ① 多边形模式裸 cast（NVN `FILL=2` → `VkPolygonMode` 的 `POINT=2`）；
  ② 图形管线缓存键里没有着色器（一轮 **15,351 次**命中错对）；
  ③ 动态偏移个数 3 vs 6、描述符池 27,756 次/轮被静默跳过。
  这三条都属于「把后端一次写全、第一帧就撞到」的东西，不该由 17 轮像素探针发现。
- **代价加倍**：① 和 ② 都是**旧路新路共有**，意味着前面若干轮「排除」是在错的管线键上做的（`DM_RASTER_BRUTE`
  那一轮已按无效样本重做）⇒ **实验本身被污染的轮次无法回收**。

### 2.4 决定四：判据换成了会翻转的代理指标

- 从 N4-h 起判据变成「已知色 152 的底子上出现非 152 = 落屏」，靠**注入自己的三角形 + 扫描读回**。
  这不是「游戏出自己的画面」，是一个代理。
- N4-p 把这个代理**自己推翻了**：同一份 5,480 字节模块，经 `vsfullf` 装载落屏、经 `vsfull` 不落 ⇒
  「落不落屏」取决于**谁装载的那个模块对象**。
- N4-q 再给出原因：两条装载路只差 `res.json` 解出的**三张数据来源表**，借表后 `ident` 从 0 → 152
  ⇒ **N4-o 那 8 格「值 × 位置」结论全部作废**（两臂不在同一数据条件下）。
- **作废样本密度**（都能在文档里逐条查到）：N4-l 那 11 轮因 `DM_TRI_FS_VARIANT` 没生效全空；N4-i 的 `vs` 档第一版
  因管线键错对作废；带层那一轮「没有判据读数」；坑 (60) 的 `97 = R32_UINT` 记错（`R32_UINT` = 98）。
- **这不是手滑，是实验形态的固有噪声**：把「整局游戏 + 一个 env 开关 + 屏幕/扫描读数」当单变量实验；
  开关一动，时序、资源注册、校验层全变（N4-p 自己就记了「带层把时序与资源注册整个改了」）。
- **正确做法**：判据优先用**用户可见终态**（截图 / 读回的那张图）或**与独立实现逐字相同的读数**；
  用代理时必须先在两臂**同条件**下验证代理本身稳定，否则代理的读数不可判。

### 2.5 决定五：把「改产物」当禁区，诊断就活成了运行期开关

- 硬约束「不许改产物」把最快的诊断手段挡住：N4-g 的 transform feedback 方案因「要给游戏那份 SPIR-V 加
  `XfbBuffer`/`Offset` 装饰」被否；N4-n 要从产物派生诊断模块，需要单独授权。
- 于是所有变换只能以**运行期开关 + 自造变体**的形式存在：`DM_TRI_LADDER` / `DM_TRI_FS_VARIANT` /
  `DM_TRI_BORROW` / `DM_PASS_PROBE` …，每个变体都是一次全量回归。
- 对照方把同类「改写 / 翻译」放在**离线打包阶段**（`make_package.py` / 数据包导入 / `build_shaders.py`），
  运行期只有一条生产路：变换是一次性的、可复现的、留在仓库外。
- **正确做法**：诊断变体一律留在 `.work/`（gitignored、离线、不进产物），产物里只允许生产路径会走到的东西。

## 3. 现在仍在重复的三处

### 3.1 两套地基并存（`DM_GFX2` 缺省关）

`vk2_pool.c:673-701`：未设 `DM_GFX2` 就回落旧路（mmap 换轨 + 8 槽 + `vkQueueWaitIdle`，即那个 10 秒级停摆的
病态路径）。后果：**状态空间 ×2、每次回归 ×2，且缺省路径是已知有病的那条**。

### 3.2 诊断物进了产物

`dm/android/vk/` 现在 17,971 行，其中约 **4.1 千行**是 `vk_tri_fs_n4*_spv.h` 这类诊断 SPIR-V 常量数组
（N4-l ～ N4-q 的变体）。它们占产物体积、参与编译、需要维护，而**生产路径不会走到**。

### 3.3 判据仍是代理 + 探针改时序

N4-r 已经转向 gfxreconstruct 抓帧（`.work/n4r_frame_*.gfxr.*`），这是对的方向（离线、可重复）；但只要
判据仍是「我们自造的底子上出现非 152」，就仍然在代理层里打转。

## 4. 对照：另一支的四个不同决定

同一宿主、同一 nvn 核心，`d2r-android` 做了四个不同的选择：

| 决定点 | `d2r-mobile`（卡住） | `d2r-android`（跑起来） |
|---|---|---|
| 客体内存 | 零拷贝别名（`vk_region.c`） | 只读快照 + 脏页增量 + 显式回读（`nvn_dirty.c` 等），生产代码 0 处 `MAP_FIXED` |
| 路径条数 | 两套地基并存，缺省走旧路 | 一条生产路 |
| 判据 | 自造底子 + 扫描读数（代理） | 同坐标营地 + 31 个 60 帧窗口 + 截图 + 计数 |
| 改产物 | 运行期开关 + 自造变体（禁区 → 排列组合） | 离线打包阶段一次性改写 |

## 5. 以后不再重复（纪律条目）

1. 任何「平台语义不同」的前提，先写一句**可证伪的读数**并在真机量一次；没量到之前不许在上面开第二轮实验。
2. **前置数据通路没走通（客体字节 → GPU 可见）不许做像素级排查**。先证明「GPU 读到的就是客体刚写的那几个字节」。
3. 判据必须是**用户可见终态**，或**与独立实现逐字相同**的读数；用代理必须先在两臂同条件下验证代理本身。
4. **一个仓库只留一条生产路径**；新地基要么默认开，要么在接管的同一个提交里删掉旧路，不允许长期并存。
5. 诊断变体留在 `.work/`，**不进产物**；产物里每一行都要能说出「生产路径会走到」。
6. 文档里已写下「此路不通」的条目，进**待改清单**；改完才允许开下一轮实验。
7. 每轮开工先写「**什么读数会推翻我**」；写不出来就不上机。
8. 每轮验证形态固定：同坐标、N 个窗口、截图 + 计数 + 帧时分解，且别人能重复。

## 6. 没被证伪的部分（避免误读）

- **宿主可复用**成立：探路 A（87 个编译单元、56 个零改动、31 处平台差异都有机械对应物）。
- **着色器链**成立：Maxwell → SPIR-V 的产物可加载（N4-k/N4-m 已把「模块内容」这一层排掉）。
- **通道 / 附件 / 布局 / 清 / 视口**这一层成立：N4-h 把自己的三角形画进**游戏的通道**里能落屏。
- **三条真 bug 是真的**：多边形模式裸 cast、管线缓存键不含着色器、动态偏移与描述符池配额。
  它们与本文的复盘**不冲突**：问题不在「有没有 bug」，而在「用多久、在哪一层找到它」。
