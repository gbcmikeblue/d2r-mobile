1. **接提交侧**（N4-b 明确留着的三行；§9.7 表的批注 ⑥ 记着）：
   · `inflight_take` / `inflight_reap` / `mtl_sub_begin` / `mtl_sub_commit`（`nvn_vk.c`）→ `vk2_sub_*`
     （旧路 8 槽轮转 → **有界在飞 3**；取槽先 `vkGetFenceStatus` 轮询、满了**只等最老那个槽的定向栅栏**、带超时；
     **上传窗口已经在 `mtl_sub_begin` 里录**，环与槽的对应关系已就绪，别改坏它）；
   · `mtl_drain` / `mtl_finish` → `vk2_sub_wait_all()`（**定向栅栏，不 `vkQueueWaitIdle`**）；
   · 收口**核心回放层那 5 处 `vkQueueWaitIdle`**（`nvn_vk.c:172/173`、`vk_tex.c:539/1167/1321`）——
     接完之后"**游戏路径上的** `vkQueueWaitIdle` 计数 = 0"这一格才有意义（G4 的第三条）。
     `vk2_upload()` 现在是"一次录完"的合体函数（§9.5 的 begin/end 两半，等真需要交错录制时再拆）。
2. **补 GPU→池的回读（往返型）** —— "出图停住"的第一嫌疑：
   · 语义：旧路里 GPU 写的是**池内存本身**（`COPY_B2B` 的目标、`UPDATE_UB` 的目标），CPU 后来读得到；
     新地基下那些写落在**后备资源**上 ⇒ 谁要读这些字节，谁就得先 `vk2_readback_after(那个 frame 的栅栏)`
     + `vk2_readback`（**没指定"等谁"就拒绝** —— N2 已经把这条纪律做成 API）。
   · 先把"谁在读"量清楚：`vk_tex_grab` / `grab_ser_locked`（贴图读回）、`mtl_read_texels`、以及旧路里
