## 口径补充（提示词之外，给你自己看的）

**为什么 N2 仍然不接管回放层**：§11.1 给 N2 的交付物是 `vk2_dirty.c/.h` + `vk2_xfer.c/.h`，判据是 **G1**（往返闭环
逐字节正确）与 **G2**（"不等待就读到旧值 / 等栅栏后读到新值"）——两者都是**探针级**的判据。把回放层换过来
（`mtl_pool_add` / `mtl_addr` / `mtl_sub_*` / `ent_upload` / `vk_tex_grab`）是 **§9.7 那张接管点表**的事，归 **N4**。
**先正确、后接管**：这样任何一块出问题都能单独回退，旧路全程可退。

**为什么 G2 是这一轮最值钱的一条**：N1 只证明了"池能建、地址能反查"；**可见性**（假设 2）还没被任何读数建立过。
G2 的两问就是这个假设的一问一答：**"不等待就读"必须读到旧值**（说明"提交完就假设 GPU 看得见"确实不成立），
**"等栅栏后读"必须读到新值**（说明定向栅栏这条路真的能建立可见性）。它也是"卡点 A（画面全零）"的期望解药，
但**不要**在这一轮去跑游戏验证画面 —— 那是 N4。

**六个新基线字段为什么不许提前填**：`每帧搬运字节数` 与 `每帧脏 run 数` 只有**真帧**才有意义（旧路那两个数
差 13 倍的前提是"这一轮健康还是生病"）。探针能给的是**机制**读数（全脏上界 = 1 run / 4096 MB / 5 条块拷贝；
位图扫一遍 0.9~2.7 ms），把它们填进帧字段就等于把 N0 那条纪律破掉。**留空 + 写清"待 N4"** 是正确的做法。

**设备口径（2026-10-16 变更）**：**第二台不使用**，新路径只用第一台 ⇒ **N5 暂缓、G5 暂不作为当前验收**。
这是"把 G5 想证的那件事换两条现在可查的顶上"（见 `ANDROID_REWRITE` §六），**不是**把判据改小：
没有第二台就**不许**写"G5 已过"，只能写"G5 留档待验"。那台 Mali 的历史与重开条件仍留在
`ANDROID_PLAN`「M3-3e」第九节，将来要扩设备时按它来。

**下一轮怎么接（N2 之后）**：把本文件「本轮目标」换成 **N3**（`vk2_sub.c/.h`：一个客体提交 = 一次
`vkQueueSubmit`、有界在飞、`vkQueueWaitIdle` 归零；判据 **G4**），并把 N2 拿到的读数（每帧搬运字节数 / 脏 run 数
的**机制**读数、G1/G2 的逐字节结论）补进提示词。工具准备的细节见 [`TOOLS.zh-CN.md`](TOOLS.zh-CN.md)。
