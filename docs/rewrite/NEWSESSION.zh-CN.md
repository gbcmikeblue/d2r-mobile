① `strtok_r` 会把 `\n` 换成 `\0`，**解析要在分词之前**；② **重录命令缓冲**的池上必须有
   `VK_COMMAND_POOL_CREATE_RESET_COMMAND_BUFFER_BIT` + 每次 `vkResetCommandBuffer`（否则表现为
   "某一条之后 `vkQueueSubmit` 开始返回 -3"，**看着像驱动的锅**）；③ 这台机的 **`malloc` 返回最高字节带 TBI
   标记的指针**（实测 `0xb400000000000000`），凡"拿地址去和 maps / 池区间比"处都要**先掩掉最高那个字节**；
   ④ `__DATE__ / __TIME__` 只反映**那一个编译单元**的编译时刻 ⇒ **不能**用它判断"设备上跑的是不是最新构建"；
   ⑤ 判"这段地址是不是普通内存 / 这次访问跨没跨块"要**把账打出来**，只报一句结论会把人引向怀疑判法本身；
   ⑥ **"一条 run 比暂存环还大"必须能切**（切片条件 = `min(块内余量, 环余量)`），否则整个窗口会被拒；
   ⑦ 高频事件（半页竞态那样一轮上万次）**必须节流**（前 N 条明细 + 之后只计数），否则读数被日志淹掉；
   ⑧ **首次提交有预热**（第一个窗口 5.9~7.2 ms，之后 519~717 µs）⇒ 首窗口要单独标出来，否则会被读成
   "每次提交都 6 ms"；
   ⑨ **判定规则本身要能回答题目、而且要写死**（N3 第一版"等待率 ≤ 25% 且长等为 0"给出 D=8、第二版"拐点"
   在 2/3 之间抖）—— 教训是：**先把要回答的那句话写下来**，再让规则只依赖与之相关的那几档；
   "长等条数"在 GPU 被塞满时**不能当否决条件**；
   ⑩ **统计快照的位置会改"总数"**（N3 第一版把基准取在三次提交之后 ⇒ 总数少 3）；两笔账对不上时**先查快照**；
   ⑪ **±1 的抖动有机制解释，别当判据不一致**：取槽先 `vkGetFenceStatus` 再 `vkWaitForFences`，"栅栏刚好在
   轮询前 signal"会让 waits / poll_reaps ±1；
   ⑫ **`adb kill-server` + `start-server` 之后前几秒 `adb devices` 是空的**（实测约 30 s 内出现）⇒ 别一读到
   空列表就要人插拔设备。

## 口径补充（提示词之外，给你自己看的）

**为什么 N4 才是"真帧第一次出现"的一轮**：§11.1 给 N4 的判据是 **M2 的验收「屏幕出（游戏自己的）画面」**
在 `DM_GFX2=1` 下通过，且 **G1~G4 仍过**；§11.3 那六个字段**全都是帧读数**，前四轮一格都填不进去
（N0/N1/N2/N3 都没跑游戏轮；N3 只把"模块内的 `vkQueueWaitIdle` = 0"这一格按口径填上）。N4 一起跑之后，
**每帧搬运字节数 / 每帧脏 run 数 / 每帧提交次数 / 长等条数与最长阻塞 / 游戏路径的 `vkQueueWaitIdle` 计数 /
槽等待率**要在**真帧**上重量一遍 —— N3 给的那些数（24 次空提交、152 次取槽、128 MB 拷贝、3.5~3.8 ms 最长等待）
**一个都不能当帧读数**。

**N4 的两件"现成待办"（前四轮量出来的，别再重新发现一遍）**：
① **暂存环按槽分**（N3：环是单窗口的，在飞 3 个槽只有 1 个能载上传窗口）—— 不然上传会把在飞深度串行化，
   而"每帧搬运字节数"这个基线读数会被它拖住；
② **半页竞态要有对策**（N2：GPU 写过的页被 CPU 部分写；随机测试一轮 20000 次里命中 5225 次）—— 绑定点上
   要么先回读该页、要么做页内字节级记账，**只报计数不够**。

**为什么接管时要一块一块来（不许一把全接）**：`DM_GFX2=1` 与旧路必须能**互切对照**（§11.5 第 1 条），
所以接管点表（§9.7）里每一行都要能单独回退；先接内存侧（`mtl_pool_add` / `mtl_addr`），再接提交侧
（`mtl_sub_*` / `mtl_drain`），最后接搬运与回读（`ent_upload` / `vk_tex_grab`）。**"屏幕出画面"是这一轮唯一
的验收**，而它一旦出现，卡点 A（画面全零）就同时有了答案。

**设备口径（2026-10-16 变更）**：**第二台不使用**，新路径只用第一台 ⇒ **N5 暂缓、G5 暂不作为当前验收**。
这是"把 G5 想证的那件事换两条现在可查的顶上"（见 `ANDROID_REWRITE` §六），**不是**把判据改小：
没有第二台就**不许**写"G5 已过"，只能写"G5 留档待验"。那台 Mali 的历史与重开条件仍留在
`ANDROID_PLAN`「M3-3e」第九节，将来要扩设备时按它来。

**下一轮怎么接（N4 之后 = N6 或 N5 留档）**：N4 过了之后，要么按 §9.7 把**原则 4（绑定以 SPIR-V 反射为唯一
真源）**单独做一块，要么进 **N6 旧路退场**（`DM_GFX_LEGACY` 双向 A/B + 待删清单，等用户一句"执行待删清单"）；

补进「已经量出来的」那一节。
