# 新路径的工具与仪器准备清单

> **什么时候用**：每一步（尤其 **N0**）开工之前照着点一遍。
> 分五类：**A 现成直接用** / **B 开工前要新做** / **C 建议补** / **D 环境与外部条件** / **E 一律不要做的"工具"**，
> 末尾一份 **F 开工前勾选表**。
> **总口径：没有读数的工具不算准备好** —— 每个工具都要写清"干什么、读数落哪、对应哪条判据"。

## B. 开工前（N0）要新做的

| 要做的 | 干什么（一问一答） | 读数落哪 | 对应判据 |
|---|---|---|---|
| **`dm/android/vk2/vk2_probe.c`（只问不接管）** | ① `maxStorageBufferRange` 是多少；② 从大到小问"能建出带 `STORAGE_BUFFER` 的 `VkBuffer` 的最大尺寸"（**块大小**的输入，已知 4 GB 带 STORAGE 建不出来）；③ 一次 `vkQueueSubmit` 装 N 条命令的开销（`VK2_INFLIGHT` 的起点）；④ "把一池全搬一遍"的字节数与耗时（**暂存环**与每帧搬运量的上界估计） | `.work/logs/probe-<串号>-vk2_probe.txt` | **N0 判据**：四个常数各有真机读数 |
| **新基线读数表** | 六个字段：每帧搬运字节数 / 每帧脏 run 数 / 每帧提交次数 / 长等条数与最长阻塞 / `vkQueueWaitIdle` 计数 / 槽等待率 | 新表（建议 `.work/logs/vk2-readings.tsv`），**不与 `ab-readings.tsv` 混** | 自 N0 起每轮记 |
| **`vkQueueWaitIdle` 自检** | 代码里放计数器，命中就报红（新地基里它必须是 0） | 日志 | **G4** |
| **跨块访问统计** | `vk2_addr` 的请求跨块时返回 0 并记"跨了块边界"（带长度分布） | 日志 | **G3** 的旁证，也是"块大小该定多少"的依据 |
| **`DM_GFX2` 开关接线（缺省关）** | 选路处：不设 = 旧路；`=1` = 新地基；启动日志自证"这次走哪条路" | 启动日志一行 | §9.10 |

## C. 建议补（都不难，但能省好几轮）

| 建议 | 为什么值得 |
|---|---|
| **探针"自证在跑"的通用写法** | 旧路踩过：保活臂因为一个初始值错，**一次都没发出去**却看着像"有效"（`ANDROID_PROGRESS` §6.3）。新探针每问一次都报"这一问真的问了没、答是什么" |
| **时间线信号量能力探针** | §9.6 要用它替掉队列锁（前端上屏与客体提交排进同一条队列的序）；先问"设备支不支持、语义对不对" |
| **`vkWaitForFences` 超时行为探针** | 有界在飞要"带超时地等栅栏"；先知道超时返回什么、之后能不能恢复 |
| **"这次绘制/拷贝用到哪些池区间"的小账本** | 脏记账第一阶段是"保守标脏"，有这个小账本才能把保守变精确，也是块大小的依据 |
| **最小往返端到端小实验** | G1/G2 的最小版：CPU 写影子 → 搬运 → GPU 拷贝 → 回读 → 与 CPU 独立算出的期望值逐字节比对。**在写 `vk2_pool` 之前先把它跑通** |

## E. 一律不要做的"工具"

- **不要**做"保活 / 加超时 / 加子"这类掩盖同步问题的东西（plan §10；`ANDROID_REWRITE` §七「明确不做」）——
  旧路已经实测过：喂空活期间那 ~10 秒照旧（保活 280 发 / 0 跳过 / 0 失败，停顿照样来）。
- **不要**为了一个读数去换设备 / 改硬件：新地基的正确性路径**不依赖**"可导出句柄"。
- **不要**在第二台上跑任何会走内存换轨 / AHB 的动作（已验证会把内核带 panic，累计 5 次）。
- **不要**把"看起来好了"当验收：判据只有 **G1~G5**。
